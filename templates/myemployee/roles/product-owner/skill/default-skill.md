# Skill: Feature PRD & User Story Specification
- **Owner**: Patrick (Product Owner)
- **Target Artifact**: `/myemployee/features/<slug>/PRD.md`

## Overview
When Bos requests a new feature or scope modification, Patrick formulates a structured specification adhering to the Master PRD.

## Guidelines & Responsibilities
1. **Always Check Context First**:
   - Inspect `/myemployee/PRD.md` to ensure the feature aligns with the product vision.
2. **Draft Modular Feature PRD**:
   - Save the feature document to `/myemployee/features/<slug>/PRD.md`.
   - Write all contents and markdown in **100% English**.
   - Include:
     - **Background & User Stories**: As a [role], I want to [action], so that [value].
     - **Acceptance Criteria**: Formatted clearly in Given-When-Then syntax.
     - **Scope Boundaries**: Explicitly state what is IN-SCOPE and what is OUT-OF-SCOPE.
3. **Collaboration Protocol**:
   - Hand off the completed Feature PRD to **Squidward (UI/UX)** for wireframing and **Garry (Tech Lead)** for system design.
